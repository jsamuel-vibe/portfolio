Superstash is the place I built to keep the things I notice online images, social posts, quotes, articles and blogs all together, so I can find them again when I need them. I made saving effortless, then discovered that was only half the problem, and redesigned around making saves useful, not just easy.

The problem

Every time something caught my attention — a UI pattern, a layout, a quote, a post, an article I wanted to read — I had nowhere real to put it. It scattered across Pinterest, screenshots, Notion, my downloads folder and messaging apps.

Saving was never the hard part. Finding it again was. I kept relearning things I already knew, simply because I'd lost track of where I'd put them. I wanted one place to keep my mind filtered: only the things worth keeping, all together, easy to find.

Why existing tools didn't work for me

So I set out to build the tool I wanted: one that captures things as fast as I notice them, without breaking what I'm doing, and without becoming another place things go to disappear.

The constraints

#1

Solo, alongside a full-time job. I couldn't build and polish everything.

#2

Core UX over visuals. I chose low-fidelity and functionally correct over slow and polished.

#3

Designed for what comes next. I made each decision with later features in mind, so I wouldn't keep changing how the tool behaves once it was in daily use.

Key decisions

Making saving frictionless, then learning it was the wrong fix

My first instinct was to remove every barrier: one click from a browser extension, with no interruption to what I was doing. It solved the loudest complaint directly — too many apps and steps just to save one thing.

But when I looked back at my own library, I'd rebuilt what I was trying to escape: a flooded, Pinterest-style dump, unsorted and overwhelming. Saving had become so easy that I stopped being selective. I'd made saving easy, not saving useful.

What I got wrong

This was my first UX project, and I made mistakes that changed how I work.

#1

Making saving frictionless, then learning it was the wrong fix

I spent a lot of time on UI and interactions, and kept generating more ideas. But I hadn't defined what the product needed to achieve, so I often didn't know what to do next.

#2

I was solving a different problem than I thought.

#3

How I course-corrected

I stopped designing and switched to building the foundation with AI-assisted coding, so the core worked first. UI and interaction polish can come once the base is in place.

What I do differently now

I define the goal and the core flow before touching UI, I build the base before polishing, and I set a timeline for every project. That habit is what got my next project, a WhatsApp campaign tool, shipped in two weeks.

Outcome and what I learned

Superstash is a personal tool, and I'm its only user so far, so there are no usage metrics. What I do have is the most important lesson from building it: simple and good are not the same thing

I designed for easy saving because it was my loudest complaint. Removing friction at the front didn't remove the problem; it moved it downstream. I only caught this because I used the tool daily and noticed my own library had become unusable in the exact way I set out to fix.
